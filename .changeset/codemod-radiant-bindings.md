Add the `migrate-radiant-bindings` transform for `@ecopages/radiant` 0.10.0, which removed the `$name` companion bindings and the `bind` option. Run `npx @ecopages/codemod migrate-radiant-bindings src`. It rewrites `this.$count` to `this.$.count` in JSX and in plain code, reads of a custom `bind: 'name'` to `this.$.<field>`, removes literal `bind` options, and adds the members it rewrote to the `RadiantElement<{ ... }>` or `RadiantController<{ ... }>` type argument. It reports with file and line what it cannot rewrite safely, such as `defineReactiveBinding`, `shouldAutoBindReactiveMembers`, `ReactiveBindingOption` imports and computed `$` access.

Add the `migrate-radiant-refs` transform for the ref/query split, which is not released yet and ships in the `@ecopages/radiant` release after 0.10.0. Run `npx @ecopages/codemod migrate-radiant-refs src`. Without renaming fields, it rewrites `@query({ ref })` to `@ref()` or `@ref('name')`, `@query({ ref, all: true })` to `@refAll`, `@query({ selector })` to `@query(selector)` or `@queryAll(selector)`, and `createQuery(host, { ... })` to `createQuery(host, selector)` or `createQueryAll(host, selector)`. It drops `cache` and updates the imports. It reports with file and line `cache: true`, `QueryConfig` imports, options it cannot read, `getReactiveMember(...).set(...)`, controller identifiers containing `:`, string `ref` attributes in JSX, and `data-hydration-key` values in files that register controllers. After the run, the CLI explains the change it cannot detect: `@ref`, `@refAll`, `getRef`, `@onEvent({ ref })` and `@bindTo({ ref })` now only see the parts their own host owns.
