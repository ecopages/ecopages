---
'@ecopages/core': minor
---

Middleware now provides typed request locals. `createMiddleware` and `composeMiddleware` are new exports: a stage passes what it provides to `next({ session })`, a later stage reads it from `ctx.locals`, and the route, group or Page that lists the middleware reads the same typed `locals` in its handler or `render`. A later entry overrides an earlier key, and a list typed as a plain array provides nothing. Plain `(ctx, next)` functions keep working and provide no types.

Breaking: `EcoMiddleware<Context>` and the form where middleware adds fields to `ctx` (`ctx.session = ...`) are removed, since a stage now provides locals through `next`. `EcoMiddleware<TLocals>` is now the type of what `createMiddleware` returns. `Middleware` and `FileRouteMiddleware` no longer take a context type parameter, and `RouteOptions` no longer takes `TRequest` and `TServer`. Listing the same middleware stage twice in one list or composition now throws when the route or Page is defined. A stage continues the chain at most once, also from a later stage it started, and `next` throws once its stage has returned. A stage that calls `next()` without awaiting, returning or catching its promise does not hide a failure of the rest of the chain: the failure propagates, while `try { await next() } catch { ... }` answers with the fallback. A middleware is listed only as `createMiddleware` or `composeMiddleware` returned it; a copy throws when the route or Page is defined.

A Page that lists a typed `middleware` array gets its `locals` from the list. `requires` still narrows the global keys it names and decides which locals reach the browser for a React Page.

A Page with `cache: 'dynamic'` now runs `props` per request with `{ request, params, query, locals, appConfig, runtimeOrigin }`, `locals` typed from the Page's `middleware` list. `props` of a static or revalidating Page keeps the build context (`params`, `appConfig`, `runtimeOrigin`) and is not called on a cache hit. The production build never calls a dynamic Page's `props`: every dynamic Page is planned from its module, and a dynamic Page's `dependencies` can no longer read `props`, only `params` and `query`. `EcoPageComponent` is now a union discriminated on `cache`, so code that reads `props` must branch on `cache`. A dynamic `props` hook called without a request throws. A `props` hook can no longer return a `params` or `query` key: `render` receives the route's Params and Query under those names, which overwrote the prop while `metadata` saw it. Returning either is a type error, and a hook that escapes the type check, such as one that returns `any`, fails when it runs.

A Page declares its Cache Strategy only on its own `eco.page()` call: a Page module that still exports `cache` now fails to load, naming the file, and `EcoPageFile` no longer has a `cache` field. A Page that sets no `cache` is not dynamic, even under `cache.defaultStrategy: 'dynamic'`: it gets no `request` or `locals`, and a `middleware` list on it throws `LocalsAccessError`; set `cache: 'dynamic'` on the Page instead.

Views rendered without a request now fail instead of being served wrong: an `app.static()` view or an explicit static route that declares `middleware`, or has `cache: 'dynamic'` and `props`, fails the build and the request, naming the route and the view's file. A custom error page that declares `middleware`, or has `cache: 'dynamic'` and `props`, throws when it renders, including the 404 page the build exports.
