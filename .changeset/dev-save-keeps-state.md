Keep component state when a page or layout is saved in development. A page, layout or component template (Kita, Lit, MDX, HTML Page) that the browser does not load as a module now refreshes the page in place when a navigation runtime such as `@ecopages/browser-router` is active, and still reloads the document otherwise. On that refresh, `@ecopages/browser-router` compares each element's previous server markup with its new server markup and keeps every element that did not change, so custom elements keep their state and stay connected, and classes or attributes added at runtime stay. On that refresh, `data-eco-rerun` scripts no longer refresh the elements around them, so a rerun script must register handlers idempotently on every element that is not replaced. A module update that reloads the active page keeps state the same way. The router records this markup only in development, so production navigation does no extra work. Two limits remain: the first save after a full page load compares against the body as the router found it at start, so a component that rendered or changed its attributes on the client before then is replaced once; and state follows tree position, so identical sibling hosts can swap state when an earlier sibling is inserted or removed. Navigation to another URL is unchanged.
