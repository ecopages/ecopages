# Data Fetching

Ecopages provides built-in functions for fetching data at build time (for static generation) and at runtime (via API handlers).

## Page Data Hooks

An `eco.page` declares its data with two hooks. **`paths` lists the Params known at build; `props` receives Params, from `paths` at build and from the request at run time.** Both return their value directly, without an envelope.

### `props`
Returns the props object of your page component. `render`, `metadata` and `dependencies` all see it.

```tsx
import { eco } from '@ecopages/core';

export default eco.page({
    props: async () => {
        // Fetch data from a database, file, or external API
        const data = await fetch('https://api.example.com/page-data').then(res => res.json());

        return {
            title: data.title,
            content: data.content,
        };
    },
    render: ({ title, content }: { title: string; content: string }) => (
        <>
            <h1>{title}</h1>
            <div>{content}</div>
        </>
    ),
});
```

A dynamic route reads the Params from `params`:

```tsx
props: async ({ params }) => ({ post: await getPost(String(params.slug)) }),
```

### `paths`
Required for a dynamic route (`[param]`) whose Cache Strategy is `'static'` or `{ revalidate }`. It returns `[{ params }]`, one entry per page to render at build. `props` is optional there: a page that only needs `params` can leave it out.

```typescript
import { eco } from '@ecopages/core';

export default eco.page({
    paths: async () => {
        const posts = await getAllPosts();
        return posts.map((post) => ({ params: { slug: post.slug } }));
    },
    // ... rest of page config
});
```

### What each Cache Strategy does

The Cache Strategy decides when the hooks run and what the build does with each entry of `paths`.

| Cache Strategy | `paths` | `props` |
| --- | --- | --- |
| `'static'` (default) | Each entry is rendered and written as HTML at build. A dynamic route without `paths` fails the build. | Runs at build for the listed Params. |
| `{ revalidate, tags }` | Same as `'static'`: each entry is rendered at build. | Runs at build for the listed Params, then at run time with the request's Params whenever the page is not cached or is revalidated: the first request after start, after a tag invalidation, or for Params not in `paths`. |
| `'dynamic'` | Optional. No HTML is written at build; each entry plans one Page Browser Graph, so scripts that depend on props are in the build. Without `paths` the page gets one plan with no Params. | Runs at build only to plan each entry, then on every request with the request's Params. |

Production builds emit the Page Browser Graphs used by browser scripts and component dependencies. If those dependencies vary by route params, return every required route instance from `paths`. `ecopages start` reuses the graphs in the build; a request that needs an unlisted graph fails instead of building it at request time. Development is unchanged.

The hooks run on the server only. `props` and `paths` are removed from the browser bundle of the page.

### Migrating from `staticProps` and `staticPaths`

`staticProps` is now `props` and `staticPaths` is now `paths`. `props` no longer wraps its result in `{ props }`, and `paths` returns the array without `{ paths }`. A page that still passes the old names fails in `ecopages dev` and `ecopages build` with an error that links here.

1. Run the codemod from your project root. It is one file, so it needs no checkout. Replace `<version>` with the Ecopages version you upgrade to (tags look like `v0.8.0`):

   ```bash
   npx jscodeshift@17 --parser tsx --extensions=ts,tsx,js,jsx -t https://raw.githubusercontent.com/ecopages/ecopages/refs/tags/v<version>/packages/codemod/src/transforms/migrate-data-hooks.ts src
   ```

   It renames both options inside `eco.page({ ... })`, unwraps the `{ props }` and `{ paths }` returns, and renames the `GetStaticProps`, `GetStaticPaths` and `StaticPath` types imported from `@ecopages/*` to `GetProps`, `GetPaths` and `PagePath`, and rewrites the `props` parameter from `{ pathname: { params } }` or `pathname.params` to `params`. A hook that reads `pathname` in another way is reported. A hook it cannot unwrap, such as one imported from another file, is left unchanged and reported. A return value it cannot see through becomes `(await value).props` or `(await value).paths`, and is reported so you can move the unwrap into your helper. Run your formatter afterwards, since the raw output indents rewritten lines with extra tabs.
2. By hand, for what the codemod reported or missed: search for `staticProps`, `staticPaths`, `GetStaticProps`, `GetStaticPaths`, `StaticPath`, `pathname.params` and `skipStaticProps`. Rename each, read `params` where `props` read `pathname.params`, rename `StaticPath` to `PagePath`, and return the value directly: `return { title }` from `props`, `return posts.map((post) => ({ params: { slug: post.slug } }))` from `paths`. Update code that reads `Page.staticProps` or `Page.staticPaths`.
3. Verify: run your type check, which fails on a leftover `GetStaticProps` or `GetStaticPaths`, then `ecopages build`. Open one dynamic route and confirm it renders the same props as before.

A page that exports `getStaticProps`, `getStaticPaths` or `getMetadata` at module level predates `eco.page()` options. Move those into the `eco.page({ ... })` options first, as the [eco namespace reference](/docs/reference/eco-namespace) shows, then follow the steps above. The `migrate-to-eco-page` codemod does both, but it only runs from a checkout of the Ecopages repository.

## Runtime Data Fetching

For dynamic applications, you can fetch data directly from your client-side scripts or through Ecopages API handlers.

### Fetching from API Handlers
Ecopages API handlers run on the Node HTTP host, whether the process is Node or Bun. They are perfect for proxying requests or interacting with a database.

```typescript
// app.ts
app.get('/api/users/:id', async ({ params, response }) => {
    const user = await db.users.find(params.id);
    return response.json(user);
});
```

### Client-Side Fetching
Standard browser `fetch` works as expected inside your `*.script.ts` files or hydrated components (React/Lit).

## Best Practices

1. **Direct Calls**: Inside `props` and `paths`, prefer direct function calls (e.g., `db.query()`) rather than calling your own API routes via HTTP to improve build performance.
2. **Type Safety**: The `eco.page` factory provides automatic type inference for your component props based on the return type of `props`.
3. **Environment Variables**: Read API keys and configuration secrets from `process.env` on the server.
