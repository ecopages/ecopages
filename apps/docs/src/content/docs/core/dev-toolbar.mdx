# Dev toolbar

The Ecopages **dev toolbar** is a development-only browser inspector. It mounts during `ecopages dev` and does not ship to production builds.

Use it to answer three common questions while building:

1. **How did this page render?** (Integration, route timing)
2. **What browser assets does this page load?** (Page Browser Graph entries, chunks, vendors)
3. **What interactive islands are on the page?** ([island hosts](/docs/core/island-hosts))

## Enable the toolbar

Install the reference package in your app and opt in from config:

```bash
pnpm add -D @ecopages/dev-toolbar
```

```typescript
import { defineConfig } from '@ecopages/core/config';
import { ecopagesJsxPlugin } from '@ecopages/ecopages-jsx';
import { devToolbar } from '@ecopages/dev-toolbar/config';

export default defineConfig({
	rootDir: import.meta.dirname,
	devToolbar: devToolbar(),
	integrations: [ecopagesJsxPlugin()],
});
```

Disable per project with `devToolbar({ enabled: false })`, or per process with `ECOPAGES_DEV_TOOLBAR=false`.

## Optional dependency

You do not need `@ecopages/dev-toolbar` unless you opt in with `devToolbar.package`. Core ships the dev manifest contract; the reference toolbar package is only required when you install and enable it.

Restart the dev server after toolbar client changes.

## Built-in apps

| App | What it shows |
| --- | --- |
| **Navigation** | URL route, owning Integration, HMR status, and client navigation timings |
| **Deps** | Page Browser Graph entry/chunk assets, vendor URLs, and dev-transform URLs from `#__ECO_DEV_MANIFEST__` |
| **Islands** | Live island hosts stamped with `data-eco-island`; click a row to highlight the DOM node |
| **A11y** | axe-core audit (with built-in fallback checks) and in-page highlights |
| **Build errors** | Current development build errors, with a badge showing distinct messages |
| **Settings** | Dock placement, stealth mode, and documentation link |

A build error opens the Build errors app automatically and reveals the toolbar in stealth mode. The next non-error HMR update clears its messages and badge. When the toolbar is disabled or no client handles the error, core displays an in-page fallback.

## Dev manifest

Each dev HTML response includes a JSON script tag:

```html
<script type="application/json" id="__ECO_DEV_MANIFEST__">…</script>
```

The toolbar reads this manifest client-side. Important fields:

| Field | Meaning |
| --- | --- |
| `route` | Absolute filesystem path of the page file that rendered this response |
| `integration` | Owning Integration plugin name for that page file (for example `react`, `kitajs`, `lit`) |
| `pageBrowserGraph` | Entry and chunk assets for the current route |
| `vendorUrls` | Vendor asset URLs referenced by the page package |
| `devTransformUrls` | Dev-transform module URLs under `/assets/__eco_dev__/` |

Import the manifest types and element id from core when building a custom toolbar client:

```typescript
import {
  DEV_MANIFEST_ELEMENT_ID,
  type EcoDevManifest,
} from '@ecopages/core/dev-toolbar/dev-toolbar-manifest-contract';
```

Machine-readable navigation history is written to `#__ECO_DEV_NAV_TELEMETRY__` in `document.head` (with `data-eco-persist` so SPA re-renders do not drop it) and exposed on `window.__ECO_DEV_NAV_TELEMETRY__.getSnapshot()` for agents and debugging.

## Island discovery

Hydratable components stamp [island host attributes](/docs/core/island-hosts). The Islands app reads `data-eco-island`, `data-eco-island-integration`, and related markers — not integration-specific selectors.

## Bring your own toolbar

Core delivers `/_dev_toolbar.js` and injects `#__ECO_DEV_MANIFEST__` on each dev HTML response. To customize the inspector, set `devToolbar.package` to your own client package and export a browser bootstrap module that mounts your toolbar UI.

Integrations do not register dock apps. Fork [`@ecopages/dev-toolbar`](https://github.com/ecopages/ecopages/tree/main/packages/dev-toolbar) for a working reference layout.

```typescript
import { defineConfig } from '@ecopages/core/config';
import { defineDevTool } from '@ecopages/core/dev-toolbar/define-dev-tool';

export default defineConfig({ devToolbar: defineDevTool('@acme/my-dev-toolbar') });
```

Custom clients can claim build errors with the browser-safe core event contract. Register the listeners before requesting pending errors; call `preventDefault()` synchronously only when your client presents a message, so unclaimed messages keep the fallback. Dismissing the fallback does not discard pending errors.

```typescript
import {
  BUILD_ERROR_EVENT,
  BUILD_ERROR_CLEAR_EVENT,
  BUILD_ERROR_REQUEST_EVENT,
  type BuildErrorDetail,
} from '@ecopages/core/dev-toolbar/build-error-contract';

export function mountBuildErrors(container: HTMLElement): () => void {
  const messages = new Set<string>();
  const onError = (event: Event) => {
    const { message } = (event as CustomEvent<BuildErrorDetail>).detail;
    if (!messages.has(message)) {
      messages.add(message);
      const entry = document.createElement('pre');
      entry.textContent = message;
      container.append(entry);
    }
    event.preventDefault();
  };
  const onClear = () => {
    messages.clear();
    container.replaceChildren();
  };
  window.addEventListener(BUILD_ERROR_EVENT, onError);
  window.addEventListener(BUILD_ERROR_CLEAR_EVENT, onClear);
  window.dispatchEvent(new Event(BUILD_ERROR_REQUEST_EVENT));
  return () => {
    window.removeEventListener(BUILD_ERROR_EVENT, onError);
    window.removeEventListener(BUILD_ERROR_CLEAR_EVENT, onClear);
    onClear();
  };
}
```
