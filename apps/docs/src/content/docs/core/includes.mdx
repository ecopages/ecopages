# Includes in Ecopages

Includes are special templates that define the document shell. They keep `<html>`, `<head>`, and SEO tags consistent across every Page.

## Basic Structure

By default, Ecopages looks for three include files under `src/includes`:

1. `html.{ext}`: The root HTML template
2. `head.{ext}`: The HTML head section
3. `seo.{ext}`: SEO-related meta tags

The extension depends on your chosen integration (`.tsx` for Ecopages JSX, `.kita.tsx`, `.lit.tsx`). Core resolves them by basename: there is no filename setter in `eco.config.ts`.

## Configuration

You do not register include filenames. Register Integrations so the resolver knows which extensions to try:

```tsx
import { defineConfig } from '@ecopages/core/config';
import { ecopagesJsxPlugin } from '@ecopages/ecopages-jsx';

export default defineConfig({
	rootDir: import.meta.dirname,
	integrations: [ecopagesJsxPlugin()],
});
```

Override the directory with `includesDir` if it is not `includes` (still relative to `srcDir`). See [Configuration](/docs/getting-started/configuration).

## Include Templates

### HTML Template

The HTML template defines the overall structure of your pages. Use `eco.html()` to signal that this component owns the full document shell:

```tsx
import { eco } from '@ecopages/core';
import type { JsxRenderable } from '@ecopages/jsx';
import './html.css';

const Html = eco.html<JsxRenderable>({
	render: ({ children, language = 'en' }) => <html lang={language}>{children}</html>,
});

export default Html;
```

`eco.html<E>()` takes one generic: the renderable (`JsxRenderable`, `ReactNode`, or the default HTML string). Props are `HtmlTemplateProps`.

### Head Template

The head template manages your document's head section:

```tsx
import { eco, type PageHeadProps } from '@ecopages/core';
import type { JsxRenderable } from '@ecopages/jsx';

const Head = eco.component<PageHeadProps<JsxRenderable>, JsxRenderable>({
	render: ({ metadata, children }) => (
	<head>
		<meta charset="UTF-8" />
		<meta name="viewport" content="width=device-width, initial-scale=1.0" />
		<title>{metadata.title}</title>
		{children}
	</head>
	)
});

export default Head;
```

Global CSS often lives here as a side-effect import (`import '../styles/tailwind.css'`), same as on pages and layouts.

### SEO Template

The SEO template handles meta tags for search engines and social sharing:

```tsx
import { eco, type PageMetadataProps } from '@ecopages/core';
import type { JsxRenderable } from '@ecopages/jsx';

const Seo = eco.component<PageMetadataProps, JsxRenderable>({
	render: ({ title, description, image, keywords }) => <>
		<meta name="description" content={description} />
		<meta name="keywords" content={keywords?.join(',')} />
		<meta property="og:title" content={title} />
		<meta property="og:description" content={description} />
		{image ? <meta property="og:image" content={image} />: null}
	</>
});

export default Seo;
```

## Best Practices

1. **Keep templates structural**: Includes own the document envelope, not page content.
2. **Import CSS next to the include**: `import './html.css'` is enough; use `dependencies.stylesheets` only for attributes such as `media`.
3. **List scripts explicitly**: inline theme bootstraps and other head scripts go in `dependencies.scripts` (string path or `{ content, attributes }`).
4. **Use one extension** for all includes, matching the Integration that owns them.
5. **Do not configure include filenames**: change `includesDir` if you must; keep `html` / `head` / `seo` basenames.
