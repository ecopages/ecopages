# Island Hosts

An **island** is a hydratable component: server HTML plus a browser script. Ecopages stamps a small, integration-agnostic attribute set on that SSR root so tools and runtimes can find it without CSS-class hacks or per-framework selectors.

You do not stamp these attributes yourself. Any `eco.component()` (or Integration equivalent) that ships a client script gets them during render.

## What that enables

- **Dev toolbar Islands panel**: list every interactive root on the page, jump to the DOM node, and see which Integration owns it. See [Dev toolbar](/docs/ecosystem/dev-toolbar).
- **Hydration targeting**: React and other Integrations can match the SSR root to the client module (stable id, optional component key, optional props snapshot).
- **Mixed rendering**: a Lit counter inside an Ecopages JSX page is still discoverable as one island, not a framework-specific custom element query.

If a component is purely presentational (no client script), it is not an island and is not stamped.

## Attributes

| Attribute | Purpose |
| :--- | :--- |
| `data-eco-island` | Marks the element as an interactive island host |
| `data-eco-island-integration` | Owning integration (`react`, `lit`, `kitajs`, `ecopages-jsx`, …) |
| `data-eco-component-id` | Stable instance id from the render pipeline |
| `data-eco-component-key` | Optional module key used by client hydration (React) |
| `data-eco-props` | Optional base64 JSON props snapshot for hydration |

React may replace the SSR host with `<eco-island>` after hydration. The marker is applied at SSR time on the component root.

## When stamping happens

Core applies island host metadata when all of the following are true:

1. The render has a component instance id
2. The result can attach attributes to a single root element
3. The render emits at least one client `script` asset

That is why a layout with only CSS is not an island, and a counter with `dependencies.scripts` is.

## Authoring a custom Integration

Call `finalizeIslandComponentRender()` on component render results that ship client scripts:

```typescript
import { finalizeIslandComponentRender } from '@ecopages/core';

return finalizeIslandComponentRender(input, {
	html,
	canAttachAttributes: true,
	rootTag: 'section',
	integrationName: 'my-integration',
	assets,
});
```

For extra hydration metadata, use `buildIslandHostAttributes()` and merge the result into `rootAttributes` before the foreign-subtree layer applies them to the first element. Prefer those helpers over inventing demo-only selectors.

| Integration | Stamping |
| :--- | :--- |
| React | `buildIslandHostAttributes()` in component SSR |
| Lit | `finalizeIslandComponentRender()` in the Lit renderer |
| KitaJS, MDX, string-markup | `finalizeIslandComponentRender()` via the string-markup renderer path |
| Ecopages JSX | `finalizeIslandComponentRender()` in the Ecopages JSX renderer |
