# Content Processor

The `@ecopages/content-processor` package scans MDX content collections at build time, validates frontmatter with [Standard Schema](https://standardschema.dev)-compatible libraries, and exposes each collection as a typed virtual module: `ecopages:content/<collection>`.

This docs app uses it for every page under `src/content/docs/`.

## Configuration

Register the processor in `eco.config.ts`:

```typescript
import { ConfigBuilder } from '@ecopages/core/config-builder';
import { compareEntriesByField } from '@ecopages/content-processor';
import { contentProcessorPlugin } from '@ecopages/content-processor/plugin';
import { withContentMdxPlugins } from '@ecopages/content-processor/mdx';
import { docsContentSchema } from './src/content/docs/docs-content.schema';

export default await new ConfigBuilder()
	.setRootDir(import.meta.dir)
	.setIntegrations([
		ecopagesJsxPlugin({
			mdx: {
				enabled: true,
				...withContentMdxPlugins({
					remarkPlugins: [remarkGfm],
				}),
			},
		}),
	])
	.setProcessors([
		contentProcessorPlugin({
			options: {
				collections: {
					docs: {
						contentDir: 'content/docs',
						schema: docsContentSchema,
						orderBy: compareEntriesByField('order'),
					},
				},
			},
		}),
	])
	.build();
```

### Docs app wiring

Navigation, section icons, and page metadata stay in `src/content/docs/content.meta.ts`. MDX modules resolve through the processor:

```typescript
import { getComponent } from 'ecopages:content/docs';

const Content = getComponent('getting-started/introduction');
```

`attachDocsContentModules()` joins `content.meta.ts` entries with `getComponent('<section>/<slug>')` — no manual MDX import map in `content.ts`.

## Package exports

- `@ecopages/content-processor` — `ContentScanner`, sort helpers, types
- `@ecopages/content-processor/plugin` — `contentProcessorPlugin()` for `eco.config.ts`
- `@ecopages/content-processor/types` — `ContentEntry`, virtual module shapes
- `@ecopages/content-processor/mdx` — `withContentMdxPlugins()` for MDX frontmatter

## TypeScript

Add generated virtual-module types to the app:

```typescript
/// modules.d.ts
import '@ecopages/content-processor/types';
```

Run `ecopages dev` or `ecopages build` before expecting IDE types for `ecopages:content/*` imports.
