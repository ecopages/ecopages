# Configuration

Ecopages can be customized to fit your project's needs through a configuration file. Create a file named `eco.config.ts` in your project's root directory to get started.

Here's a basic example of an Ecopages configuration:

```typescript
import { defineConfig } from '@ecopages/core/config';
import { ecopagesJsxPlugin } from '@ecopages/ecopages-jsx';

export default defineConfig({
	integrations: [ecopagesJsxPlugin()],
	defaultMetadata: {
		title: 'Your Site Title',
		description: 'Your site description',
		image: 'https://your-domain.com/og-image.png',
	},
});
```

`createApp()` loads and finalizes this file automatically. Override the path with `createApp({ configFile })`, `ECOPAGES_CONFIG_FILE`, or `ecopages dev --config <file>`.

In development, adding, changing, or removing `eco.config.ts` or a supported project `.env` file restarts the dev server so integrations, directories, and environment values reload. Supported files are `.env`, `.env.local`, `.env.[NODE_ENV]`, and `.env.[NODE_ENV].local`. If the restarted dev server exits with an error, for example because of an invalid `eco.config.ts`, `ecopages dev` waits for the next change to the config or a dotenv file and starts again. Page and component files still hot-reload without a full restart.

## Configuration API

<ApiField name="rootDir" defaultValue="process.cwd()" type="string">
	The root directory of your project, used to resolve paths to your project files.
</ApiField>

<ApiField name="baseUrl" defaultValue="http://localhost:3000" type="string">
	The base URL of your project, used for generating absolute URLs for your pages. `ECOPAGES_BASE_URL` overrides the default when `baseUrl` is omitted.
</ApiField>

<ApiField
	name="defaultMetadata"
	type="PageMetadataProps"
	defaultValue="{ title: 'Ecopages', description: 'This is a static site generated with Ecopages' }"
>
	Default metadata for your pages. This is merged with page-specific metadata when provided.
</ApiField>

<ApiField name="srcDir" type="string" defaultValue="src">
	The directory containing your source files, relative to the root project directory.
</ApiField>

<ApiField name="publicDir" type="string" defaultValue="public">
	The directory for static assets, relative to the src directory.
</ApiField>

<ApiField name="pagesDir" type="string" defaultValue="pages">
	The directory containing your page files, relative to the src directory.
</ApiField>

<ApiField name="includesDir" type="string" defaultValue="includes">
	The directory for include templates, relative to the src directory.
</ApiField>

<ApiField name="layoutsDir" type="string" defaultValue="layouts">
	The directory for layout components, relative to the src directory.
</ApiField>

Ecopages now discovers the document shell and error pages semantically:

- `src/includes/html.*` resolves the HTML template by basename and integration extension.
- `src/pages/404.*` resolves the not-found page by basename and integration extension.
- `src/pages/500.*` resolves the server-error page by basename and integration extension.

`eco.config.ts` has no field for these filenames. If no `pages/500.*` file or `app.serverError()` loader is configured, the page pipeline serves a built-in HTML 500 page. In development, custom and default 500 pages can show `message` and `stack` from the thrown error; the built-in page also includes a **Copy error** button.

<ApiField name="distDir" type="string" defaultValue="dist">
	The output directory for the built files.
</ApiField>

<ApiField name="workDir" type="string" defaultValue=".eco">
	The internal workspace used for development and runtime-only artifacts. This directory is not intended for
	deployment.
</ApiField>

<ApiField name="componentsDir" type="string" defaultValue="components">
	The directory containing your reusable components.
</ApiField>

<ApiField name="additionalWatchPaths" type="string[]" defaultValue="[]">
	Add additional files or directories to monitor during development. Paths are resolved from the project root, so
	`src/registry` watches every file inside that folder. Glob patterns such as `**/*.config.ts` are also supported. A
	matching change invalidates server modules, notifies processors, and reloads the browser.
</ApiField>

<ApiField
	name="robotsTxt"
	type="{ preferences: RobotsPreference }"
	defaultValue={`{ preferences: { "*": [] } }`}
>
	Configuration for the robots.txt file.
</ApiField>

<ApiField
	name="sitemap"
	type="SitemapConfig"
	defaultValue="{ enabled: false, fileName: 'sitemap.xml', extraUrls: [], exclude: [] }"
>
	Automatic <code>sitemap.xml</code> generation during static export. Disabled by default. See{' '}
	<a href="/docs/core/sitemap">Sitemap</a> for eligibility rules, <code>exclude</code> patterns, and{' '}
	<code>extraUrls</code>.
</ApiField>

<ApiField name="integrations" type="IntegrationPlugin[]" defaultValue="[]">
	An array of integration plugins to enhance Ecopages functionality.
</ApiField>

<ApiField name="processors" type="Processor[]" defaultValue="[]">
	An array of processors to handle file transformations (e.g., PostCSS, Images).
</ApiField>

<ApiField name="loaders" type="EcoBuildPlugin[]" defaultValue="[]">
	An array of build plugins to use as loaders for custom file types.
</ApiField>

<ApiField name="sourceTransforms" type="EcoSourceTransform[]" defaultValue="[]">
	Filter-based module source rewrites for browser and HMR builds. See [Source
	Transforms](/docs/plugins/source-transforms).
</ApiField>

<ApiField name="cache" type="CacheConfig">
	Page cache settings: `store` (default `'memory'`), `defaultStrategy` for Pages that set none (default `'static'`),
	`enabled` (on in production builds, off in watch mode unless set), and `maxEntries` for the memory store (default
	`1000`). See [Caching](/docs/server/caching).
</ApiField>

<ApiField name="devPrewarmPaths" type="string[]" defaultValue="[]">
	Routes such as `/` or `/docs` to render in the background when the development server starts, so the first visit is
	fast.
</ApiField>

<ApiField name="devPrewarmBeforeReadyPaths" type="string[]" defaultValue="[]">
	Routes the development server renders before it reports ready. Keep this list short.
</ApiField>

<ApiField name="experimental" type="{ unsafe?: Record<string, unknown> }">
	Short-lived private toggles under `unsafe`, with no validation. Do not rely on them.
</ApiField>

<ApiField name="devToolbar" type="DevToolbarConfig">
	Development-only in-browser inspector. Install `@ecopages/dev-toolbar` and set `devToolbar: devToolbar()`. See
	[Dev toolbar](/docs/core/dev-toolbar).
</ApiField>

## Integrations

Ecopages supports various integrations to extend its capabilities. Here are some commonly used integrations:

- **Ecopages JSX**: Default stack for `.tsx` Pages and optional Radiant hydration
- **React**: React Pages or component islands
- **Lit**: Web Components
- **MDX**: Standalone Markdown on a non-React JSX runtime
- **KitaJS**: `.kita.tsx` Pages via `@kitajs/html`

To use an integration, install it and add it to your configuration. For example:

```typescript
import { defineConfig } from '@ecopages/core/config';
import { ecopagesJsxPlugin } from '@ecopages/ecopages-jsx';

export default defineConfig({
	rootDir: import.meta.dirname,
	baseUrl: process.env.ECOPAGES_BASE_URL ?? 'http://localhost:3000',
	integrations: [ecopagesJsxPlugin()],
});
```

For more details on specific integrations, refer to their respective documentation pages:

- [Ecopages JSX Integration](/docs/integrations/ecopages-jsx)
- [KitaJS Integration](/docs/integrations/kitajs)
- [Lit Integration](/docs/integrations/lit)
- [MDX Integration](/docs/integrations/mdx)
- [React Integration](/docs/integrations/react)
