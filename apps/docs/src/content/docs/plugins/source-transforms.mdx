# Source Transforms

Source transforms rewrite module source during server, browser, and HMR builds. Register them in your configuration when you need deterministic, filter-based code rewrites without competing with processor `onLoad` plugins.

Prefer source transforms over ad hoc `EcoBuildPlugin` `onLoad` handlers when the change is a pure source rewrite. Builds run source transforms in the bundler's transform hook, after the module is loaded, so metadata injection and similar passes still run on output rewritten by `onLoad` plugins.

## EcoSourceTransform Shape

```typescript
import type { EcoSourceTransform } from '@ecopages/core/plugins/source-transform';

const bannerTransform: EcoSourceTransform = {
	name: 'file-banner',
	filter: /entry\.tsx$/,
	enforce: 'pre',
	transform(code, id) {
		return { code: `/* transformed: ${id} */\n${code}` };
	},
};
```

Fields:

- `name` — stable identifier
- `filter` — `RegExp` tested against module ids without query or hash, with `/` separators on every platform. It alone decides which modules the transform sees, so keep it narrow; virtual modules are never transformed
- `enforce` — optional `'pre'` or `'post'` ordering (default runs between pre and post)
- `transform(code, id)` — returns rewritten source, `{ code, map? }`, or `undefined` to skip. `id` has no query or hash.

Return `map` whenever the rewrite moves code, for example when it inserts a line. The bundler chains it with the other source maps, so stack traces and the emitted source maps point at the source the author wrote. Without `map`, positions after the edit are off by its size.

## Registration

Register transforms in `eco.config.ts`:

```typescript
import { defineConfig } from '@ecopages/core/config';
import { ecopagesJsxPlugin } from '@ecopages/ecopages-jsx';

export default defineConfig({
	rootDir: import.meta.dirname,
	baseUrl: process.env.ECOPAGES_BASE_URL ?? 'http://localhost:3000',
	sourceTransforms: [
		{
			name: 'test-source-transform',
			filter: /entry\.tsx$/,
			transform(code) {
				return { code: `/* source transform */\n${code}` };
			},
		},
	],
	integrations: [ecopagesJsxPlugin()],
});
```

## Vite Host Bridge

When Ecopages runs inside a Vite host, adapt app-owned transforms into Vite-compatible plugins:

```typescript
import { createVitePluginsFromAppSourceTransforms } from '@ecopages/core/plugins/source-transform';
import appConfig from './eco.config';

const viteTransforms = createVitePluginsFromAppSourceTransforms(appConfig);
```

See [Vite Plugin](/docs/ecosystem/vite-plugin) for host integration.

## Choosing the Right Extension Point

| Mechanism | Use when |
| --- | --- |
| `EcoSourceTransform` | Filter-based source rewrites during builds |
| `EcoBuildPlugin` (`onLoad` / `onResolve`) | Virtual modules, custom loaders, or resolve-time behavior |
| Processor `plugins` | Runtime file processing owned by a processor |
| Processor `buildPlugins` | Browser-only bundling behavior owned by a processor |
| Integration `browserBuildPlugins` | Framework-specific browser transforms or import aliasing |
