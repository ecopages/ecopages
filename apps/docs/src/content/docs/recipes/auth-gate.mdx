# Auth-gated layout

Use this when the same URL must render differently for signed-in and signed-out visitors, or send signed-out visitors elsewhere. It uses page middleware, request locals and a layout, with no auth library; swap in yours for the session check.

Two patterns, both in the fixture:

- **Gate in the layout.** The page's middleware stores the session in `locals`, and the layout renders the page or a sign-in screen. Use it when the URL stays the same.
- **Redirect in the middleware.** The middleware returns a redirect before the page renders. Use it when signed-out visitors belong on another URL.

## What the test checks

The fixture's end-to-end test runs against `ecopages dev` and `ecopages start`. A request without a cookie gets the sign-in screen and not the dashboard heading. A request with a session cookie gets the dashboard. `/account` answers `302` to `/sign-in` without a session, and the endpoint answers `303` with a `Set-Cookie` and a redirect to `/dashboard`. The dev run also asserts the layout's children warning below.

## Caveats

- **A layout that drops `children` is allowed, and reported.** The gate renders without its page on purpose. In `ecopages build` that would fail, as `Layout <name> (<file>) did not render its children`, but a dynamic page is not built. A development request logs the message as a warning, and a production request returns the HTML silently. See [Layouts](/docs/core/layouts#layout-components).
- **The page still renders.** The layout only chooses whether to include its output. The page's `render` runs for a signed-out visitor too, so load private data in the middleware after the session check, not in `render`. The redirect pattern never reaches `render` without a session.
- **The gate answers `200`.** If a signed-out visitor should get `401`, or a crawler should not index the sign-in screen, return that response from the middleware instead.
- **`requires` is a type, not a check.** `requires: ['session']` narrows `locals.session` in `render` and does not verify it. The middleware must enforce it, as `requireSession` does.
- **Do not cache the response.** Dynamic pages are rendered per request. Keep the page `dynamic`; a cached or static page would show one visitor's version to everyone.
- **The cookie is a demo.** Use `HttpOnly`, `Secure` and `SameSite` attributes and a value your server can verify.
