# Deployment

Deploying an Ecopages application depends on whether you are using only static features or if you've added API routes and server-side logic.

## Production Build

Before deploying, you must create a production build. This processes your assets, pre-renders static pages, and prepares the `dist` directory.

For projects using the [Vite host plugin](/docs/ecosystem/vite-plugin), `ecopages build` still produces the same `dist` output; Vite orchestrates dev and optional build integration only.

```bash
pnpm run build
```

This command will:

1. Set `NODE_ENV=production`.
2. Clean the `dist` directory.
3. Generate static HTML for all files in `src/pages`.
4. Write `robots.txt` (and optional `sitemap.xml` when enabled — see [Sitemap](/docs/core/sitemap)).
5. Process images and CSS.
6. Collect all necessary server-side files.

---

## Static Hosting

If your site **does not** use API routes or programmatic server logic, you can host the contents of the `dist` directory on any static provider.

- **Vercel / Netlify**: Connect your repository and set the build command to `pnpm run build`. Set the output directory to `dist`.
- **GitHub Pages**: Use a GitHub Action to run `pnpm run build` and deploy the output directory.

## Server Hosting (Node/Bun)

If your application uses **API routes** or **dynamic server logic**, you need a runtime environment compatible with the adapter you configured (Bun or Node).

### 1. Using `pnpm run start`

After building, you can start the production server:

```bash
pnpm run start
```

### 2. What to deploy

`ecopages build` writes the server into `dist/.server/`. The server code holds no absolute paths of the machine that built it: it loads packages from `node_modules` through bare imports or paths relative to `dist/.server/`. You can build in one place and run in another, such as a CI runner and a container image with a different root. Copy these entries of your project and keep their relative positions:

- `dist/`: the server bundle, its config and the static export.
- `src/`: the server reads your routes from `src/pages` at startup.
- `node_modules/`: the install the build ran against.
- `package.json`.

Copy the `node_modules` the build used, installed on the same operating system and CPU architecture as the server, because packages with native bindings install files for one platform. Some imports point into the package manager's own folders, such as `node_modules/.pnpm/<name>@<version>_<peers>/`, so a fresh install only works when it produces the same folder names: same lockfile, same package manager version and same layout settings (for pnpm `node-linker`, `virtual-store-dir` and `virtual-store-dir-max-length`; for Bun the linker).

Start the server from that folder with `node dist/.server/app.mjs`, or `bun dist/.server/app.mjs` with the Bun adapter. Leave `eco.config.ts` out, or start with `ecopages start`: either way the server loads the config compiled into `dist/.server/`.

In a monorepo, the packages live in the workspace root `node_modules`, outside your app folder. Build from a standalone copy of the app instead, for example the output of `pnpm deploy`. A production build warns in one line, listing the packages, when the server imports packages from outside the app folder.

### 3. Docker Deployment

You can easily containerize your Ecopages app using the official Bun image when using the Bun adapter.

```dockerfile
FROM oven/bun:latest

WORKDIR /app

COPY package.json ./
RUN bun install --production

COPY . .
RUN bun run build

EXPOSE 3000
CMD ["bun", "run", "start"]
```

To build in one stage and run in another, copy the entries listed above. Both stages use the same base image, so native bindings match. Add `node_modules` and `dist` to `.dockerignore`, or `COPY . .` overwrites the image's install with the one from your machine:

```dockerfile
FROM node:24-slim AS build
WORKDIR /build
RUN corepack enable
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile
COPY . .
RUN pnpm run build

FROM node:24-slim
WORKDIR /srv/app
ENV NODE_ENV=production ECOPAGES_HOSTNAME=0.0.0.0
COPY --from=build /build/package.json ./
COPY --from=build /build/node_modules ./node_modules
COPY --from=build /build/dist ./dist
COPY --from=build /build/src ./src

EXPOSE 3000
CMD ["node", "dist/.server/app.mjs"]
```

### 4. VPS / PaaS (Railway, Fly.io)

Deploy the server by pointing the platform to your `app.ts` as the entry point and ensuring it runs with the `start` command in production.

## Environment Check

Before going live, check that these environment variables are set on your hosting provider:

| Variable            | Recommended Value                                    |
| :------------------ | :--------------------------------------------------- |
| `NODE_ENV`          | `production`                                         |
| `ECOPAGES_BASE_URL` | Your production domain (e.g., `https://example.com`) |
| `ECOPAGES_PORT`     | The port required by your host (e.g., `8080`)        |
| `ECOPAGES_HOSTNAME` | `0.0.0.0` (for Docker/Cloud environments)            |
