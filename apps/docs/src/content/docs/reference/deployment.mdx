# Deployment

Deploying an Ecopages application depends on whether you only export static HTML or you also serve API routes and request-time pages.

`createApp()` selects **Node** or **Bun** from the running process (`adapter: 'auto'`). Match the production image to the runtime you build with, or pass `adapter: 'node'` / `adapter: 'bun'` explicitly.

## Production Build

Create a production build before deploying. This processes assets, pre-renders static pages, and prepares `dist`.

For projects using the [Vite host plugin](/docs/ecosystem/vite-plugin), `ecopages build` still produces the same `dist` output; Vite orchestrates dev and optional build integration only.

```bash
pnpm build
```

This command will:

1. Set `NODE_ENV=production`.
2. Clean the `dist` directory.
3. Generate static HTML for pages with a static cache strategy.
4. Write `robots.txt` and, when enabled, `sitemap.xml`. See [Sitemap](/docs/core/sitemap).
5. Process images and CSS.
6. Emit the server bundle and `dist/.server/eco.config.mjs` when the app has a server.

## Static Hosting

If your site **does not** use API routes, middleware, or dynamic cache strategies, host the contents of `dist` on any static provider.

- **Vercel / Netlify**: Connect the repository. Build command `pnpm build` (or `npm run build`). Output directory `dist`.
- **GitHub Pages**: Run `pnpm build` in CI and publish the output directory.
- **Any object store / CDN**: Upload `dist` after a CI build with `ECOPAGES_BASE_URL` set to the public origin.

## Server Hosting

If the application uses **API routes**, **dynamic pages**, or **request-time logic**, run `ecopages start` (or your `start` script) on a long-lived Node or Bun process. The production server loads the emitted config from `dist`, not `eco.config.ts`.

### 1. Using `pnpm start`

After building:

```bash
pnpm build
pnpm start
```

Point the host at `0.0.0.0` and the port it assigns:

```bash
ECOPAGES_HOSTNAME=0.0.0.0 ECOPAGES_PORT=8080 pnpm start
```

### 2. Docker (Node)

```dockerfile
FROM node:22-alpine

WORKDIR /app

COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile --prod=false

COPY . .
RUN pnpm build

ENV NODE_ENV=production
ENV ECOPAGES_HOSTNAME=0.0.0.0
ENV ECOPAGES_PORT=3000

EXPOSE 3000
CMD ["pnpm", "start"]
```

Use a multi-stage build if you want a smaller runtime image (copy `dist`, production `node_modules`, and `package.json` only).

### 3. Docker (Bun)

Use this only when the app is built and started with Bun (`adapter: 'bun'` or a Bun process):

```dockerfile
FROM oven/bun:latest

WORKDIR /app

COPY package.json ./
RUN bun install --production

COPY . .
RUN bun run build

ENV ECOPAGES_HOSTNAME=0.0.0.0
EXPOSE 3000
CMD ["bun", "run", "start"]
```

### 4. VPS / PaaS (Railway, Fly.io, Render)

Set the start command to `pnpm start` (after a build step). The entry is still `app.ts`, compiled into the server bundle. Do not point the platform at `eco.config.ts`.

## Environment Check

Set these on the build (static URLs) and/or the runtime (listen address):

| Variable            | Recommended Value                                    |
| :------------------ | :--------------------------------------------------- |
| `NODE_ENV`          | `production`                                         |
| `ECOPAGES_BASE_URL` | Your production domain (e.g., `https://example.com`) |
| `ECOPAGES_PORT`     | The port required by your host (e.g., `8080`)        |
| `ECOPAGES_HOSTNAME` | `0.0.0.0` (for Docker/Cloud environments)            |
