# Explicit Routing

Explicit routing defines handlers, middleware, validation, and rendered views in your `app.ts` file.

## Overview

Use filesystem Pages for routes that map naturally to files. Use explicit routing for APIs, middleware-heavy routes, or applications that keep route registration in one place.

For architectural patterns and code organization examples, see [Routing Patterns](./routing-patterns).

## Basic Routes

Define routes using HTTP method functions on your app instance:

```typescript
import { createApp } from '@ecopages/core/create-app';

const app = await createApp();

app.get('/api/users', async (ctx) => {
	const users = await getUsers();
	return ctx.json(users);
});

app.post('/api/users', async (ctx) => {
	const body = await ctx.request.json();
	const user = await createUser(body);
	return ctx.json(user, { status: 201 });
});

await app.start();
```

## Rendering Views

The `ctx.render()` method renders `eco.page` views from a route handler. Register the view's Integration in `eco.config.ts`; Ecopages then selects that Integration from the transformed component identity.

Load views through the server-module transpiler so Node applies component-identity transforms. `ctx.renderServerModule()` is the usual choice inside route handlers:

```typescript
import { HttpError } from '@ecopages/core/errors';

app.get('/posts/:slug', async (ctx) => {
	const post = await getPost(ctx.params.slug);
	if (!post) {
		throw HttpError.NotFound('Post not found');
	}
	return ctx.renderServerModule(new URL('./src/views/post-view.kita', import.meta.url), post);
});
```

		`app.get()` is the API pipeline. `HttpError.NotFound` here becomes JSON (or your `app.onError()` response). To
		serve the HTML not-found page, throw from an `app.static()` page or leave the URL unmatched. See

### Partial Rendering

Use `ctx.renderPartial()` to render without layout (useful for dynamic fragments):

```typescript
app.get('/comments', async (ctx) => {
	const comments = await getComments();
	return ctx.renderPartial(CommentList, { comments });
});
```

### Response Helpers

```typescript
// JSON response
ctx.json(data, { status: 200, headers: {...} })

// HTML response
ctx.html('<h1>Hello</h1>', { status: 200 })

// Full view with layout
ctx.render(View, props, { status: 200 })

// View without layout
ctx.renderPartial(View, props)
```

## Route Groups

Group routes with shared prefix and optional middleware:

```typescript
app.group('/api/v1', (r) => {
	r.get('/users', listUsers);
	r.post('/users', createUser);
	r.get('/users/:id', getUser);
});

app.group('/api/admin', (r) => {
	r.get('/stats', getStats);
	r.post('/config', updateConfig);
}, { middleware: [authMiddleware] });
```

Routes within a group inherit the prefix and middleware. You can also add per-route middleware:

```typescript
app.group('/api', (r) => {
	r.get('/public', publicHandler);
	r.get('/protected', protectedHandler, { middleware: [authMiddleware] });
}, { middleware: [loggingMiddleware] });
```

## Middleware

Middleware functions intercept requests before they reach the handler.

### Defining Middleware

```typescript
import type { Middleware } from '@ecopages/core';

const authMiddleware: Middleware = async (ctx, next) => {
	const token = ctx.request.headers.get('Authorization');
	if (!token) {
		return ctx.response.status(401).json({ error: 'Unauthorized' });
	}
	return next();
};

const logMiddleware: Middleware = async (ctx, next) => {
	console.log(`${ctx.request.method} ${ctx.request.url}`);
	return next();
};
```

### Extending Context with Middleware

Middleware can extend the request context with additional properties (like session data, user info, etc.). Use the `EcoMiddleware` helper type to define middleware that adds properties to the context:

```typescript
import type { EcoMiddleware } from '@ecopages/core';

const authMiddleware: EcoMiddleware<{ session: Session }> = async (ctx, next) => {
	const session = await getSession(ctx.request.headers);
	if (!session) {
		return Response.redirect('/login');
	}
	ctx.session = session; // Add session to context
	return next();
};
```

The context type is **automatically inferred** from the middleware you provide - no need to manually specify it:

```typescript
app.group(
	'/admin',
	(r) => {
		r.get('/', async (ctx) => {
			// ctx.session is fully typed automatically!
			console.log(ctx.session.userId);
			return ctx.render(AdminDashboard, { user: ctx.session.user });
		});

		r.post('/posts', async (ctx) => {
			const post = await createPost({
				...ctx.body,
				authorId: ctx.session.userId
			});
			return ctx.json(post);
		});
	},
	{ middleware: [authMiddleware] } // Type inferred from here!
);
```

The extended context properties are fully type-safe across all handlers in the group.

### Per-Route Middleware

```typescript
app.post('/api/posts', createPost, {
	middleware: [authMiddleware, logMiddleware]
});
```

## Request Validation

EcoPages supports [Standard Schema](https://github.com/standard-schema/standard-schema) for type-safe request validation. Use any compatible library: Zod, Valibot, ArkType, or Effect Schema.

### Basic Validation

```typescript
import { z } from 'zod';

app.post('/api/posts', async (ctx) => {
	const { title, content } = ctx.body;
	return ctx.json({ id: 1, title, content });
}, {
	schema: {
		body: z.object({
			title: z.string().min(1),
			content: z.string()
		})
	}
});
```

### Validation Targets

| Target | Description | Access |
|--------|-------------|--------|
| `body` | Request body (JSON) | `ctx.body` |
| `query` | Query string parameters | `ctx.query` |
| `headers` | Request headers | `ctx.headers` |
| `params` | Route path parameters | `ctx.params` |

These properties contain parsed data. When schemas are provided, they contain validated and type-safe data. For raw access, use `ctx.request.body`, `ctx.request.url`, and `ctx.request.headers`.

### Path Params Validation

```typescript
app.get('/api/users/:id', async (ctx) => {
	return ctx.json({ userId: ctx.params.id });
}, {
	schema: {
		params: z.object({
			id: z.string().uuid()
		})
	}
});
```

### Validation in Route Groups

```typescript
app.group('/api', (r) => {
	r.post('/users', createUser, {
		schema: {
			body: z.object({
				name: z.string(),
				email: z.string().email()
			})
		}
	});
}, { middleware: [authMiddleware] });
```

### Query Validation

Query parameters are strings by default, but schemas can coerce and validate them:

```typescript
app.get('/api/posts', async (ctx) => {
	const { page, limit, sortBy } = ctx.query;
	// page: number, limit: number, sortBy: 'date' | 'title' | 'views'
	const posts = await getPosts({ page, limit, sortBy });
	return ctx.json(posts);
}, {
	schema: {
		query: z.object({
			page: z.coerce.number().min(1).default(1),
			limit: z.coerce.number().min(1).max(100).default(20),
			sortBy: z.enum(['date', 'title', 'views']).default('date')
		})
	}
});
```

### Header Validation

Validate required headers like API keys or webhook signatures:

```typescript
// API key authentication
app.post('/api/webhooks', async (ctx) => {
	const apiKey = ctx.headers['x-api-key'];
	// apiKey is guaranteed to be a valid UUID
	return ctx.json({ received: true });
}, {
	schema: {
		headers: z.object({
			'x-api-key': z.string().uuid()
		})
	}
});

// Webhook signature validation
app.post('/webhooks/stripe', async (ctx) => {
	const signature = ctx.headers['stripe-signature'];
	const isValid = verifyStripeSignature(ctx.body, signature);
	return ctx.json({ verified: isValid });
}, {
	schema: {
		body: z.any(),
		headers: z.object({
			'stripe-signature': z.string().min(1)
		})
	}
});
```

### Validation Errors

Invalid requests automatically receive a 400 response:

```json
{
	"error": "Validation failed",
	"issues": [
		{ "path": ["title"], "message": "String must contain at least 1 character(s)" }
	]
}
```

## Error Handling

HTML error pages and API errors are different pipelines. `app.onError()` does not run for `app.static()` failures or unmatched URLs.

| Source | `HttpError.*` | Generic `Error` |
| :--- | :--- | :--- |
| Unmatched URL | None | HTML **404** |
| `app.static()` `staticProps` / `render` | HTML with that status | HTML **500** |
| `app.get()` / groups / `app.add()` | JSON with that status | `app.onError()` or JSON 500 |

`HttpError.BadRequest` (400), `Unauthorized` (401), `Forbidden` (403), `NotFound` (404), `Conflict` (409), and `InternalServerError` (500) each have a semantic HTML page. Other 4xx statuses use a built-in document; other 5xx statuses reuse the 500 page with the original status. `HttpError` values outside the valid 400–599 error range normalize to 500.

### API errors

Throw `HttpError` from `app.get()` and related handlers:

```typescript
import { HttpError } from '@ecopages/core/errors';

app.get('/api/posts/:slug', async (ctx) => {
	const post = await getPost(ctx.params.slug);
	if (!post) {
		throw HttpError.NotFound('Post not found');
	}
	return ctx.json(post);
});
```

Available factory methods:

```typescript
HttpError.BadRequest(message?, details?)
HttpError.Unauthorized(message?)
HttpError.Forbidden(message?)
HttpError.NotFound(message?)
HttpError.Conflict(message?, details?)
HttpError.InternalServerError(message?)
```

### Global Error Handler

`app.onError()` centralizes **API** error handling (logging, JSON shape). It does not replace HTML 404/500 pages.

```typescript
app.onError((error, ctx) => {
	if (error instanceof HttpError) {
		return ctx.json(error.toJSON(), { status: error.status });
	}
	console.error('Unhandled error:', error);
	return ctx.json({ error: 'Internal Server Error' }, { status: 500 });
});
```

## HTML error pages

Register `eco.page` modules when the app has no matching `src/pages/{status}.*`. Filesystem semantic pages still win when they exist.

```typescript
app.notFound('./src/views/not-found.kita');
app.forbidden('./src/views/forbidden.kita');
app.serverError('./src/views/server-error.kita');
app.errorPage(409, './src/views/conflict.kita');
```

String and URL paths load through the server-module transpiler (HMR and component identity in development). Raw dynamic `import()` skips those transforms.

When neither a filesystem error page nor an app loader is configured, Ecopages serves built-in HTML defaults with **inline CSS only** (not your app Tailwind or PostCSS pipeline). Stable hooks:

| Hook | Usage |
| :--- | :--- |
| `eco-error-page` | Root `<body>` class on built-in pages |
| `eco-error-page--bad-request` / `--unauthorized` / `--forbidden` / `--not-found` / `--conflict` / `--server-error` | Status modifier |
| `eco-error-page__title`, `eco-error-page__message`, `eco-error-page__stack` | Text regions |
| `eco-error-page__copy` | Development-only copy button on the default 500 page (adds `eco-error-page__copy--copied` after a successful copy) |
| `eco-error-page__copy-icon`, `eco-error-page__copy-label` | Clipboard / check icons and label text |

Custom pages use your layout and assets. Typical class names: `error404`, `error500`, `error500__stack`, `error500__actions`.

### Preview HTML error pages

Throw the matching `HttpError` from `staticProps` or `render`. Throw a generic `Error` only when you mean a server failure. Use `cache: 'dynamic'` on a demo route if you do not want it in static export.

```typescript
import { eco } from '@ecopages/core';
import { HttpError } from '@ecopages/core/errors';

export default eco.page({
	cache: 'dynamic',
	render: () => {
		throw HttpError.Forbidden('Admin only');
	},
});
```

```bash
curl -i http://localhost:3000/does-not-exist
# HTTP/1.1 404

curl -i http://localhost:3000/forbidden
# HTTP/1.1 403

curl -i http://localhost:3000/boom
# HTTP/1.1 500
```

In development, custom and built-in 500 pages can show escaped `message` and `stack`. Production omits those props. 4xx pages receive the public `HttpError` message. The built-in 500 page includes a **Copy error** button.

The `playground/explicit-routes` app wires `/boom` (500), `/forbidden` (403), and `app.notFound()` / `app.forbidden()` / `app.serverError()`. Restart `pnpm dev` after changing `app.ts`.

## Static Generation

Register `eco.page` modules for build-time static generation. String and URL paths load through the same transpiler as `renderServerModule`, including HMR in development.

```typescript
app.static('/posts', './src/views/post-list.kita');
app.static('/posts/:slug', './src/views/post-view.kita');
```

The default export must define `staticPaths` (for dynamic segments) and `staticProps`. `staticProps` receives `{ pathname, appConfig, runtimeOrigin }`: not a top-level `params` argument.

```typescript
// src/views/post-view.tsx
import { eco } from '@ecopages/core';
import { HttpError } from '@ecopages/core/errors';

const PostView = eco.page<PostViewProps>({
	staticPaths: async () => {
		const posts = await getPosts();
		return {
			paths: posts.map((post) => ({ params: { slug: post.slug } })),
		};
	},

	staticProps: async ({ pathname }) => {
		const post = await getPost(pathname.params.slug as string);
		if (!post) {
			throw HttpError.NotFound('Post not found');
		}
		return { props: { title: post.title, content: post.content } };
	},

	render: (props) => <article>...</article>,
});

export default PostView;
```

## Views Outside pages/

Define `eco.page` views anywhere in your codebase. Views used with `app.static()` or rendered via dynamic import must be the default export:

```typescript
// src/views/post-view.tsx
import { eco } from '@ecopages/core';
import { MainLayout } from '@/layouts/main-layout';
import './post-view.css';

const PostView = eco.page<PostViewProps>({
	layout: MainLayout,

	metadata: ({ title, authorName }) => ({
		title: `${title} | My Blog`,
		description: `By ${authorName}`
	}),

	render: ({ title, content }) => (
		<article>
			<h1>{title}</h1>
			<div>{content}</div>
		</article>
	)
});

export default PostView;
```

## Coexistence with File-System Routing

Explicit routes take precedence over file-system routes:

```typescript
const app = await createApp();

// Explicit routes (higher priority)
app.get('/posts', posts.index);
app.get('/posts/:slug', posts.show);

// File-system routes still work
// /about -> pages/about.tsx
// /contact -> pages/contact.tsx

await app.start();
```

## Complete Example

```typescript
import { createApp } from '@ecopages/core/create-app';
import { HttpError } from '@ecopages/core/errors';
import { z } from 'zod';
import { PostView, PostListView } from './src/views';
import type { EcoMiddleware } from '@ecopages/core';

const app = await createApp();

const authMiddleware: EcoMiddleware<{ session: Session }> = async (ctx, next) => {
	const session = await getSession(ctx.request.headers);
	if (!session) throw HttpError.Unauthorized();
	ctx.session = session;
	return next();
};

// Static pages (string paths load through the server transpiler on Node)
app.static('/posts', './src/views/post-list.kita');
app.static('/posts/:slug', './src/views/post-view.kita');
app.notFound('./src/views/not-found.kita');
app.forbidden('./src/views/forbidden.kita');
app.serverError('./src/views/server-error.kita');

// Public API
app.group('/api/v1', (r) => {
	r.get('/posts', async (ctx) => {
		const posts = await getPosts();
		return ctx.json(posts);
	});
});

// Protected API with validation and typed context
app.group('/api/v1/admin', (r) => {
	r.post('/posts', async (ctx) => {
		const { title, content } = ctx.body;
		const post = await createPost({
			title,
			content,
			authorId: ctx.session.userId // Fully typed from middleware!
		});
		return ctx.json(post, { status: 201 });
	}, {
		schema: {
			body: z.object({
				title: z.string().min(1),
				content: z.string()
			})
		}
	});
}, { middleware: [authMiddleware] });

// API-only error handler (does not cover app.static() HTML 404/500)
app.onError((error, ctx) => {
	if (error instanceof HttpError) {
		return ctx.json(error.toJSON(), { status: error.status });
	}
	return ctx.json({ error: 'Internal Server Error' }, { status: 500 });
});

await app.start();
```
