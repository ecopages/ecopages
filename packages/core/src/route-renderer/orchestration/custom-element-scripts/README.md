# Custom element SSR script preload

Shared orchestration for `dependencies.scripts` entries marked `ssr: true`.

Lit and Ecopages JSX construct a {@link CustomElementScriptPreloader} with a stable `cacheScope` so imports are deduplicated across concurrent renders and dev invalidation can clear preload state without per-renderer registries.

Server evaluation uses `appConfig.runtime.appModuleLoader` via {@link createCustomElementServerModuleImporter} when no {@link createCustomElementSsrPreloadEntrypointResolver} is configured. Lit's render session passes a resolver so Node and Bun both preload through the asset pipeline. The Lit static-render worker has no session, so `LitRenderer` skips the resolver and uses {@link createCustomElementServerModuleImporter}, which compiles a separate module per registry. The resolver skips {@link importServerModule}. Each custom-element registry then imports its own copy of that module, written beside the pipeline file and removed once evaluated: Bun ignores a query-only URL change for every module, so a query cannot register the element on the next registry. The copy keeps the pipeline file's package scope and relative resolution. Ecopages JSX does not pass a resolver. On Bun, `preferSourceImports` imports the script source in place. On Node it imports through the page server-module loader with external packages, because the dev asset pipeline still points at `.tsx` source and a browser bundle would register a second Radiant graph. The copy is only for a pipeline file whose path differs from the source. A source import (`preferSourceImports`, or a pipeline that returns the source path) stays in place and still isolates registries with the `eco-ssr-registry` query, which only Node honours.

Lit only preloads lazy `ssr: true` script entries (`requireLazyScriptEntry`) so eager registrations are not evaluated in an isolated graph that would break `@lit-labs/ssr`. Ecopages JSX sets `collectForIntegration` so foreign integration scripts in shared dependency trees are not preloaded here; Lit and other hosts keep owning their registrations.
