# Project Watcher

**Layer:** Development and HMR.

The Project Watcher recursively watches `srcDir` and any configured pages, components, includes, layouts or public directory that resolves outside it, plus recorded build inputs outside it, restart files, workspace-linked package roots used by recorded build inputs, and configured additional watch paths. Recorded inputs include files loaded through build plugins, module closures, and Processor watch roots; they select which builds and caches a change invalidates without narrowing source-directory coverage. A workspace package root is activated only after a recorded build input resolves inside it; inputs recorded after startup activate their package root then. Startup waits up to 30 seconds for the `@ecopages/file-system` subscription to become ready before the server advertises readiness, so the first edit cannot race filesystem subscription. A startup error or timeout closes the watcher and rejects initialization. The filesystem adapter indexes existing paths without emitting initial changes. When the native event omits its filename, the adapter can report a `rescan` for mapped requested roots; the Project Watcher coalesces those into a runtime restart request because the changed path is unknown. Subscription replays paths already recorded during initialization or Page rendering and adds paths recorded after listen. Genuine new source files invalidate immediately, including files copied with preserved timestamps. Creates in active linked-package roots still request a restart.

Filesystem events use a trailing debounce with a 150 ms default; setting `changeDebounceMs` to `0` disables debouncing. `ECOPAGES_WATCH_CHANGE_DEBOUNCE_MS` supplies the value when the option is unset; a value that is not a non-negative number logs a warning and the default applies. A changed public file is copied into `distDir` and a deleted one is removed from it, and either reloads the browser. With debouncing enabled, the maximum-wait timer schedules the batch no later than one second after its first event. Processing remains serialized behind earlier work, so it can start later. Closing the watcher drops scheduled batches that have not started. File and directory events share the same debounce window. The watcher submits one file batch to `DevelopmentInvalidationService`; a runtime-restart category returns its path without marking results dirty, then the watcher forwards it to the runtime owner. Other batches mark server modules, Page Browser Graph records, HTML cache entries, and route-module records dirty without rebuilding them. An unopened Page is rebuilt on the next request. For each non-restart file batch, matching Processors receive one `onChanges({ created, changed, deleted, bridge })` callback; an error thrown by one is logged and shown in the browser error overlay, and the remaining Processors and the client update still run. The watcher passes every HMR-eligible file from that batch to the HMR manager in one call; the manager dispatches each file to its strategy and coalesces their results into one client update. Directory-only Pages batches refresh the Route Registry once without Processor or HMR notifications.

At startup it resolves the application's declared dependencies, development dependencies, and optional dependencies through installed package directories, including hoisted installs, then follows declared dependencies of linked packages to find transitive linked roots. A real package root outside `node_modules` is watched only when a recorded build input lies within that package. This covers server-only imports and packages with subpath-only exports after they are used, without waiting for a browser request. Missing optional packages are skipped; aliases to the same root share a subscription.

Adding, changing, or removing a file in an active linked-package root requests a runtime restart before HMR or Processor notifications. The existing lifecycle coalesces pending restart requests and delegates shutdown to the process that owns the watcher. The next process reloads server imports and rebuilds browser vendors from memory; vendor bundles are not persisted under `dist`. A watcher with no restart callback warns and returns.

Linked package `node_modules` and dot entries are ignored. Application work and dist directories remain ignored, while application dotenv files remain restart inputs. Discovery runs again on startup; changing the application's dependency declarations or links requires restarting the session.
