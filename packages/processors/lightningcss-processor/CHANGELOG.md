## 0.7.0

### Minor Changes

- [#1117](https://github.com/ecopages/ecopages/pull/1117) [`423a59b`](https://github.com/ecopages/ecopages/commit/423a59bbb66dc8c5aba5f33acdc62430d88df189) Thanks [@andeeplus](https://github.com/andeeplus)! - Scope CSS Modules. A `*.module.css` file gets class names built from `[hash]_[local]`, hashed from its path relative to the app, so they match across folders; set `cssModules: { pattern }` to change the pattern. `composes` and `composes ... from` work, and the class map lists the composed names after each class.

- [#1130](https://github.com/ecopages/ecopages/pull/1130) [`0a0e9cd`](https://github.com/ecopages/ecopages/commit/0a0e9cdeff94077bf63d20678db3dd54c195b221) Thanks [@andeeplus](https://github.com/andeeplus)! - Scope the CSS Modules of packages. The class names of a package's `*.module.css` hash the package name and the path inside the package, so they are identical across machines, folders and package-manager layouts, and the `preprocessor` does not run on a package file.

- [#1141](https://github.com/ecopages/ecopages/pull/1141) [`dc05316`](https://github.com/ecopages/ecopages/commit/dc053160d2b317b7a11e4cd4cbb64370f22e8b7f) Thanks [@andeeplus](https://github.com/andeeplus)! - `lightningCssProcessorPlugin` takes a `plugins` option: a list of `{ name, transformSource?(css, file), visitor? }`. `transformSource` rewrites a stylesheet before Lightning CSS parses it and before the Tailwind v4 preset runs, so `@apply` works in what it writes; `visitor` is a Lightning CSS visitor, composed with the `visitor` option. Plugins run in array order on the entry, every imported partial (including the ones the Tailwind preset inlines) and every CSS Module.

    The first plugin is `suffixNesting()` from `@ecopages/lightningcss-processor/plugins/suffix-nesting`, an opt-in for Sass-style suffix nesting. Lightning CSS stays standard by default, so `&--primary`, `&__element` and `&-item` still fail the build unless the plugin is listed. With it, `.button, a.button { &--primary { ... } }` becomes `.button--primary, a.button--primary { ... }`, placed after the rule it came from, and the rules nested in it keep working. A parent that is not one compound selector, such as `.card .title`, fails with the file, line, column and selector.

    The error for suffix nesting now lists every pair in a selector, points at the plugin, and gives a type selector after `&` (`&div`) its own message.

- [#1111](https://github.com/ecopages/ecopages/pull/1111) [`eee240a`](https://github.com/ecopages/ecopages/commit/eee240a34676282a0d4f80304a4a140d31910123) Thanks [@andeeplus](https://github.com/andeeplus)! - Add `@ecopages/lightningcss-processor`, a stylesheet Processor that runs Lightning CSS. It bundles `@import` with its `layer()`, `supports()` and media conditions, resolving relative paths, tsconfig aliases and packages as core does. It lowers the CSS for browserslist `targets`, minifies in production, and keeps root-relative and remote imports external at the top of the output. Editing a nested partial rebuilds the stylesheets that import it, and a stylesheet error fails the build with its file and position. It replaces the PostCSS Processor in an app, which has one stylesheet Processor.

- [#1140](https://github.com/ecopages/ecopages/pull/1140) [`834dac5`](https://github.com/ecopages/ecopages/commit/834dac5d7122d5183140af81231aa09d79eb9209) Thanks [@andeeplus](https://github.com/andeeplus)! - A stylesheet with Sass-style suffix nesting, such as `.button { &--primary { ... } }` or `&__element`, now fails the build instead of losing the rule without a message. Native CSS nesting cannot concatenate selectors, so the rule never matched. The error names the file, line, column and the selector, and says to write the full selector, such as `.button--primary`. In development it shows in the error overlay and the last good stylesheet stays until a save fixes it.

    This is a minor change before 1.0 because a build that used to succeed with the rule silently missing now fails.

- [#1121](https://github.com/ecopages/ecopages/pull/1121) [`0514b64`](https://github.com/ecopages/ecopages/commit/0514b64e8e042c02a7fc74c152078c282d0632b9) Thanks [@andeeplus](https://github.com/andeeplus)! - Add `tailwindV4Preset({ referencePath })` at `@ecopages/lightningcss-processor/presets/tailwind-v4`, so Tailwind v4 runs inside the Lightning CSS Processor without PostCSS. Each stylesheet goes through Tailwind, then through the Processor's own bundling, `targets`, minifying and CSS Modules. `@tailwindcss/node`, `@tailwindcss/oxide` and `tailwindcss` are optional peer dependencies.

    A stylesheet that uses `@apply`, and every CSS Module, gets an `@reference` to `referencePath`, placed after its leading `@charset`, `@layer` and `@import` statements. In development, a saved template that uses a new class rebuilds only the stylesheets that scan it, and a file Tailwind does not scan rebuilds nothing.

    The Processor takes a `preprocessor` option, a stage that runs on every stylesheet before Lightning CSS, which presets use.

- [#1137](https://github.com/ecopages/ecopages/pull/1137) [`e7a129b`](https://github.com/ecopages/ecopages/commit/e7a129ba19003015bad6e64d40b191a46276273c) Thanks [@andeeplus](https://github.com/andeeplus)! - Require Node.js `^24.22.0 || >=26.0.0`, declared in `engines.node`. Node 24 releases before 24.22 and Node 25 are no longer supported, because older Node 24 releases report file deletions unreliably in the Linux recursive watcher. Upgrade Node.js before updating.
