Discoverability is split across two paths in this template:

- **RSS** is app-owned. `app.ts` writes `/rss.xml` before the server starts.
- **Sitemap** is framework-owned. `setSitemap()` in `eco.config.ts` emits `sitemap.xml` after static export.

Both reuse the post collection you explored in the earlier articles.

## RSS at startup

RSS is generated in `app.ts` before the server starts. The feed is written to `src/public/rss.xml` and served like any static file.

### 1. Scan posts with ContentScanner

`generateRss` reuses the same schema and sort order as the content processor, so the feed matches the site.

```ts
// app.ts
await generateRss({
  contentRoot: path.join(appRoot, 'src', POSTS_CONTENT_DIR),
  schema: postsFrontmatterSchema,
  orderBy: comparePosts,
  postPathPrefix: '/posts',
  channel: { title: 'EcoBlog', description: 'A content-driven Ecopages React blog.' },
});
```

### 2. Render RSS 2.0 XML

Each item includes title, link, description, and `pubDate` from the ISO `date` frontmatter field.

### 3. Write to public/

The output lands in `src/public/rss.xml`. Ecopages copies public assets into `dist/` during export. Open [/rss.xml](/rss.xml) after starting the app.

### 4. Advertise the feed

The layout links to the feed in the header, and `<link rel="alternate">` in `Seo` helps aggregators discover it.

## Sitemap during export

Unlike RSS, `sitemap.xml` is owned by Ecopages core. Enable it in config and it is written automatically after static export.

### 1. Opt in with setSitemap

Sitemap generation is disabled by default. This template enables it and lists the RSS URL as an extra non-page location.

```ts
// eco.config.ts
.setSitemap({
  enabled: true,
  extraUrls: ['/rss.xml'],
  exclude: ['/404', '/500'],
})
```

### 2. Collect eligible routes

Static pages that export successfully and allow indexing are included. Pages with `robots.index: false` are omitted.

### 3. Append extraUrls

`/rss.xml` is not a page route, so it is listed through `extraUrls` after page URLs are resolved.

### 4. Write after export hooks

The sitemap is written after `afterStaticExport`, so integrations can finish generating artifacts first. Set `ECOPAGES_BASE_URL` before building for production.

## How they fit together

| Artifact | Generated by | When | Listed in sitemap |
| --- | --- | --- | --- |
| `/rss.xml` | `generateRss()` in `app.ts` | App startup / build entry | Yes, via `extraUrls` |
| `/posts/*` | Static page export | `ecopages build` | Yes, when indexable |
| `sitemap.xml` | Ecopages core | After static export hooks | N/A |

Set `ECOPAGES_BASE_URL` to your production origin before running `ecopages build` so absolute URLs in the feed and sitemap resolve correctly.
